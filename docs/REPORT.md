# Milestone report

All numbers from `scripts/bench.sh` on an AMD Ryzen 7 4700G (8 cores / 16
threads), release build, exact arithmetic throughout.  Instances are
generated by `scripts/gen.py` (files in `inputs/`).  "visited" counts reverse
search tree nodes over all facet searches (a `∂U` vertex on `f` facets is
visited `f` times and emitted once); "bases" is the number of `d`-subsets of
`H_v` factorised by the kernel; "terms" the number with non-zero signed
weight `χ_B`; "depth" the maximal tree depth; "stackdirs" the maximal number
of edge directions held on the stack (the traversal's working memory);
"rss" the peak resident set (`VmHWM`).

## Milestones 1–3: sweep-plane half, driven by the brute-force enumerator

* SPEC §3.3 self-check (unit square, `a = (1,2)`): contributions
  `λ²/4, −(λ−1)²/4, −(λ−2)²/4, (λ−3)²/4`; `s(5) = 1`, `s(1) = 1/4`
  (`tests/oracle_sweep.rs`).
* Golden values: unit and rational boxes and standard simplices for
  `d = 1…5`; cube with `a = (1,1,1)` against the closed form; square pyramid,
  octahedron, 4-D cross-polytope (every vertex degenerate), a cone with 24
  planes through the apex; L-shape, nested, disjoint, adjacent, touching
  unions, four squares around an interior vertex, three triangles whose
  perturbation opens a hole (`tests/golden.rs`).
* Invariants enforced on every run: `s` is zero below the smallest knot and
  constant above the largest (`SweepFunction::total` rejects any non-zero
  higher coefficient in the last piece); direction independence of the total
  over random directions.

## Milestone 4: reverse search with the fused kernel

Differential test (`tests/common/mod.rs::differential`): for every instance
above, the multiset of vertices emitted by the reverse search equals the
oracle's `∂U` vertex set with multiplicity exactly one, and the knot maps
are identical.  Debug builds additionally assert that the root has no
improving edge and that every ratio-test neighbour stays in the facet.

**Memory is flat in the vertex count.**  Single thread, growing unions of
sheared boxes in `R^3`:

Visited vertices grow 230×, resident memory 3.7×.  What does grow is

## Milestone 5: non-generic sweep directions

`tests/nongeneric.rs`: axis directions on boxes give the expected
lower-degree pieces (`s = λ` on `[0,1]` for the square with `a = (1,0)`);
six non-generic directions on a 3-polytope union give the generic total and
match Monte Carlo at intermediate `λ`; `--assume-generic` fails with a clear
message.  The Laurent poles are accumulated and checked to cancel per knot.

## Milestone 6: parallelism, hybrid arithmetic, benchmarks

Thread scaling on `boxes3d_160` (960 facet tasks, budget 2000 nodes):

| threads | search time | speedup | peak RSS |
|---:|---:|---:|---:|
|  1 | 8.93 s | 1.0× | 10.7 MB |
|  2 | 4.66 s | 1.9× | 14.0 MB |
|  4 | 2.47 s | 3.6× | 20.5 MB |
|  8 | 1.97 s | 4.5× | 32.2 MB |
| 16 | 1.45 s | 6.2× | 52.4 MB |

(8 physical cores; the 16-thread row uses SMT.)  Results are bit-identical
for every thread count and budget (`tests/golden.rs::budget_splitting_is_exact_and_deterministic`).

Arithmetic: `Z` is `i128` promoted to `BigInt` on overflow; the hot scans
(hyperplane evaluation at a vertex, ratio test) run on a flat `i64` mirror of
the arrangement with `i128` accumulators whenever coefficients are below
`2^31` and coordinates below `2^62`, and fall back otherwise
(`tests/bigint.rs` exercises 30-digit coefficients).  These fast paths gave a
3.7× single-thread speedup over the first version.

Cross-checks against `lrs` (lrslib-073 via `scripts/lrs_check.py`): the
volumes of all 276 convex pieces of the shipped instances (`lshape3d,
boxes3d_20/40/60, boxes4d_12, boxes5d_10, boxes6d_6, rand3d_20, rand4d_8/24,
rand5d_6, cones3d_30x3, grid3d_4`) are recorded in `tests/lrs_golden.txt`
and checked exactly by `tests/lrs_golden.rs`; lrs is not needed to run the
suite.

## Milestone 7: CLI and I/O

`volume`, `sweep` (`--at`, `--json`), `plot` (CSV samples); `.ine` with
several blocks or several `--input` files, JSON; `--threads`, `--budget`,
`--assume-generic`, `--oracle`, `--seed`, `-v`, `--stats-json`.  Unbounded,
empty and lower-dimensional inputs exit with code 2 and a message.

## What was not done, and why

* **Local structure cache keyed by combinatorial type (SPEC §4.2).**  The
  profile is dominated by the `O(|H|·d)` hyperplane scans per node (one per
  visited vertex plus one ratio test per tested edge), not by the local
  kernel; caching local structures would not move the needle.  Scratch
  buffers are reused where it is free.
* **Vertices visited more than once across facets.**  A `∂U` vertex is
  visited once per facet containing it, and arrangement vertices interior
  to `U` that lie on a facet plane are visited too; this is inherent to the
  per-facet convex restriction that makes the search a tree.  The ratio
  visited/emitted is 1.3–7.5 on the instances above.
